# 简单网关服务产品文档

## 1. 产品定位

简单网关服务为多个用户提供隔离的 HTTP 路由配置与反向代理能力。用户通过后台注册、登录、绑定鉴权服务组，并为自己的外部入口配置路由规则。运行时网关入口为 `/gw/{userSlug}/...`，系统只会匹配该 `userSlug` 所属用户的启用路由。

本次版本的核心安全目标是：受保护路由不能只因为访问者知道网关链接就被放行。路由必须显式选择访问模式，链接泄露后的风险由访问模式决定。

外部鉴权服务地址默认为 `https://auth-service.baichengedu.com`。

## 2. 用户与隔离

注册需要填写用户名、用户 slug、密码、邀请码、鉴权服务组名称和鉴权服务组永久授权码。

注册规则：

- 邀请码必须等于 `.env` 中的 `INVITE_CODE`。
- 用户名和用户 slug 必须唯一。
- 服务组名称和永久授权码必须能通过鉴权服务的 `POST /api/service-groups/token/latest` 校验。
- 校验失败时不创建用户。

用户登录成功后服务端签发 HttpOnly Cookie 会话。后台页面和管理接口都必须携带有效会话。

所有用户私有数据都按 `user_id` 隔离，包括服务组绑定、路由规则、请求头规则和响应头规则。用户只能查看、创建、更新和删除自己的数据。运行时 `/gw/{userSlug}` 也只使用该 slug 对应用户的启用路由，不会跨用户匹配。

## 3. 路由访问模式

每条路由必须选择一个访问模式：

- `public`：公开访问。命中路由后直接转发到上游，不做网关鉴权。适合公开资源、健康检查或上游自身已经完整鉴权的服务。
- `caller_token`：调用方 token 访问。请求必须携带 `Access-Token`，网关调用外部鉴权服务校验成功后才转发。链接本身不具备访问能力，是受保护路由的默认模式。
- `signed_link`：短期签名链接访问。请求必须携带网关签发的 `gw_expires` 和 `gw_signature` 查询参数，签名有效且未过期才转发。适合临时分享，不适合长期固定入口。

`caller_token` 和 `signed_link` 都需要填写鉴权服务名称。保存路由时，系统会使用当前用户绑定的服务组校验该服务是否已注册且归当前服务组管理。

### 3.1 调用方 token 模式

运行时规则：

- 请求必须携带 `Access-Token`。
- `Service-Name` 优先使用请求头；如果请求头缺失，使用路由配置的鉴权服务名称。
- 网关透传 `Origin`、`Referer`、`model` 给鉴权服务。
- 鉴权失败时不访问上游。

该模式不会在请求缺少 `Access-Token` 时自动使用用户绑定的服务组 token 兜底，因此泄露普通链接不会绕过鉴权。

### 3.2 短期签名链接模式

签名链接由登录后的管理 API 生成。签名绑定以下信息：

- HTTP 方法。
- 完整网关路径，例如 `/gw/alice/report/2026`。
- 业务查询参数，不包含 `gw_expires` 和 `gw_signature`。
- 过期时间戳。

访问时必须携带：

- `gw_expires`：Unix 秒级过期时间。
- `gw_signature`：base64url 编码的 HMAC-SHA256 签名。

网关校验签名后会移除 `gw_expires` 和 `gw_signature`，再把剩余业务查询参数转发给上游。签名过期、签名不匹配、路径被改动、方法被改动或业务查询参数被改动时，访问都会失败。

## 4. 路由管理

用户可在后台管理自己的路由规则。每条路由包含：

- 名称、描述和启用状态。
- 访问模式。
- 匹配方式：前缀匹配或精确匹配。
- 外部路径。
- HTTP 方法。
- 上游基础地址。
- 是否去除匹配前缀。
- 超时时间、重试次数和优先级。
- 鉴权服务名称。
- 请求头 set/remove 规则。
- 响应头 set/remove 规则。

如果访问模式为 `public`，鉴权服务名称会被清空，保存时不执行服务归属校验。如果访问模式为 `caller_token` 或 `signed_link`，鉴权服务名称必填，保存时必须通过服务组归属校验。

已有历史路由升级规则：

- 原 `auth_required=false` 的路由迁移为 `public`。
- 原 `auth_required=true` 的路由迁移为 `caller_token`。
- 旧版 API 中的 `authRequired=true` 仍会被兼容解析为 `caller_token`。

## 5. 网关转发

运行时入口为：

```text
/gw/{userSlug}/{path}
```

处理流程：

1. 根据 `userSlug` 查询用户。
2. 只读取该用户启用的路由。
3. 根据 HTTP 方法、匹配方式、优先级和最长路径选择路由。
4. 按路由访问模式完成鉴权或签名校验。
5. 按路由规则重写路径、应用请求头规则并转发到上游。
6. 返回上游响应，并应用响应头规则。

常见响应：

- 用户或路由不存在：404。
- 路由存在但方法不允许：405。
- 缺少凭证、签名过期或签名无效：401。
- 外部鉴权服务拒绝：403。
- 上游不可达：502。
- 上游超时：504。

## 6. 管理 API

管理 API 登录后通过 `gateway_session` HttpOnly Cookie 鉴权。

路由 API 使用 `accessMode` 字段表示访问模式。为了兼容旧客户端，系统继续接受 `authRequired`，但新客户端应使用 `accessMode`。

签名链接生成接口：

```http
POST /api/routes/{id}/signed-link
Content-Type: application/json
```

请求体：

```json
{
  "method": "GET",
  "path": "/report/2026",
  "query": "format=pdf",
  "expiresInSeconds": 3600
}
```

成功返回：

```json
{
  "url": "https://gateway.example.com/gw/alice/report/2026?format=pdf&gw_expires=1780000000&gw_signature=...",
  "method": "GET",
  "expiresAtUnix": 1780000000
}
```

只有 `signed_link` 模式的路由允许生成签名链接。生成时路径和方法必须能命中该路由。

## 7. 管理后台 UI

后台页面包括登录页、注册页、路由列表页、路由新增/编辑页和服务组换绑页。

UI 要求：

- 路由表单提供访问模式选择。
- 选择 `caller_token` 或 `signed_link` 时，鉴权服务名称为必填项。
- 路由列表展示启用状态、匹配方式、外部路径、上游地址、访问模式和更新时间。
- 表单错误在页面中展示明确原因。
- 用户只能看到自己的路由。

## 8. 公共使用说明接口

服务提供无需登录的 `GET /api/public/usage` 接口，供外部服务了解本服务能力。

接口返回服务名称、版本、通用约定、管理 API 列表、网关调用方式、请求头、请求体、返回体和错误码说明。该接口不返回用户私有配置、授权码、access token 或签名密钥。

## 9. 安全边界

- `public` 路由不防止链接泄露。
- `caller_token` 路由以调用方 token 为访问凭证，链接泄露不应导致越权访问。
- `signed_link` 路由在签名有效期内仍可能被持有链接的人访问，因此应设置较短有效期。
- 服务组永久授权码只用于注册、换绑和保存受保护路由时的服务归属校验，不再作为运行时无凭证请求的兜底通行凭证。
- 日志不得输出 `Access-Token`、Cookie、授权码、签名值、请求 body 或响应 body。

## 10. 后续扩展

v1 不内置以下能力，但保留扩展空间：

- 路由限流。
- 熔断。
- 上游健康检查。
- 访问日志查询。
- 审计日志。
- 多邀请码或一次性邀请码。
