# 简单网关服务产品文档

## 1. 产品定位

简单网关服务为多个用户提供隔离的 HTTP 路由配置与反向代理能力。用户通过后台注册、登录、绑定鉴权服务组，并为自己的外部入口配置路由规则。运行时网关入口为 `/gw/{userSlug}/...`，系统只会匹配该 `userSlug` 所属用户的路由规则。

本服务支持两类路由：

- 非鉴权路由：命中路由后直接转发到上游服务。
- 鉴权路由：转发前调用外部鉴权服务校验，成功后才访问上游。

外部鉴权服务地址默认为 `https://auth-service.baichengedu.com`。

## 2. 用户与隔离

### 2.1 用户注册

注册需要填写：

- 用户名。
- 用户 slug，用作公网入口 `/gw/{userSlug}/...`。
- 密码。
- 邀请码。
- 鉴权服务组名称。
- 鉴权服务组永久授权码。

注册规则：

- 邀请码必须等于 `.env` 中的 `INVITE_CODE`。
- 用户名和用户 slug 必须唯一。
- 服务组名称和永久授权码必须能通过鉴权服务的 `POST /api/service-groups/token/latest` 校验。
- 校验失败时不创建用户。

### 2.2 登录与会话

用户使用用户名和密码登录。登录成功后服务端签发 HttpOnly Cookie 会话。后台页面和管理接口都必须携带有效会话。

### 2.3 数据隔离

所有用户私有数据都按 `user_id` 隔离，包括：

- 服务组绑定。
- 路由规则。
- 请求头与响应头规则。

用户只能查看、创建、更新和删除自己的数据。运行时 `/gw/{userSlug}` 也只使用该 slug 对应用户的启用路由，不会跨用户匹配。

## 3. 鉴权服务组绑定

用户注册时必须绑定服务组，登录后可以换绑。

换绑需要填写：

- 新服务组名称。
- 新永久授权码。

系统会重新调用 `POST /api/service-groups/token/latest` 校验匹配关系。校验成功后，服务组名称和授权码密文会替换旧绑定。

永久授权码不以明文保存。系统使用 `.env` 中的 RSA 私钥推导公钥，每次保存前生成随机 salt，并使用 RSA-OAEP-SHA256 加密结构化明文。

## 4. 路由管理

用户可在后台管理自己的路由规则。

### 4.1 路由字段

每条路由包含：

- 名称。
- 描述。
- 启用状态。
- 匹配方式：前缀匹配或精确匹配。
- 外部路径。
- HTTP 方法：ALL、GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS。
- 上游基础地址。
- 是否去除匹配前缀。
- 超时时间。
- 重试次数。
- 优先级。
- 是否需要鉴权。
- 鉴权服务名称。
- 请求头 set/remove 规则。
- 响应头 set/remove 规则。

### 4.2 鉴权路由创建规则

如果路由选择“需要鉴权”：

- 必须填写鉴权服务名称 `authServiceName`。
- 系统先使用当前绑定的服务组永久授权码调用 `POST /api/service-groups/token/latest` 获取服务组 access token。
- 系统再调用 `POST /api/auth/verify`，请求头为：
  - `Service-Name: {serviceGroupName}`
  - `Target-Service-Name: {authServiceName}`
  - `Access-Token: {groupToken}`
- 只有鉴权服务已注册且当前绑定服务组有权限管理该服务时，路由才允许保存。

如果路由不需要鉴权，则无需填写鉴权服务名称，也不会执行服务归属权限校验。

## 5. 网关转发

运行时入口为：

```text
/gw/{userSlug}/{path}
```

处理流程：

1. 根据 `userSlug` 查询用户。
2. 只读取该用户启用的路由。
3. 根据 HTTP 方法、匹配方式、优先级和最长路径选择路由。
4. 如果路由需要鉴权，先完成鉴权。
5. 按路由规则重写路径、应用请求头规则并转发到上游。
6. 返回上游响应，并应用响应头规则。

常见响应：

- 用户或路由不存在：404。
- 路由存在但方法不允许：405。
- 鉴权失败：401 或 403。
- 上游不可达：502。
- 上游超时：504。

## 6. 运行时鉴权规则

鉴权路由转发前必须调用 `POST /api/auth/verify`。

如果外部请求携带 `Access-Token`：

- 使用请求方提供的 `Access-Token`。
- `Service-Name` 优先使用外部请求头。
- 如果外部请求没有 `Service-Name`，使用路由配置的 `authServiceName`。
- 透传 `Origin`、`Referer`、`model` 给鉴权服务。

如果外部请求没有携带 `Access-Token`：

- 使用当前用户绑定服务组的永久授权码换取服务组 access token。
- `Service-Name` 使用绑定服务组名称。
- `Target-Service-Name` 优先使用请求头 `Service-Name`，否则使用路由配置的 `authServiceName`。
- 校验失败则不访问上游。

## 7. 管理后台 UI

后台使用 Go HTML 模板实现，与 API 同服务部署。

页面包括：

- 登录页。
- 注册页。
- 路由列表页。
- 路由新增/编辑页。
- 服务组换绑页。

UI 要求：

- 所有表单错误都在页面中展示明确原因。
- 鉴权路由中鉴权服务名称为必填项。
- 路由列表展示启用状态、匹配方式、外部路径、上游地址、鉴权状态和更新时间。
- 用户只能看到自己的路由。

## 8. 公共使用说明接口

服务提供无需登录的 `GET /api/public/usage` 接口，供外部服务了解本服务能力。

接口返回：

- 服务名称与版本。
- 通用约定。
- 管理 API 列表。
- 网关调用方式。
- 请求头、请求体、返回体说明。
- 错误码。

该接口不返回用户私有配置、授权码或 access token。

## 9. 后续扩展

v1 不内置以下能力，但保留扩展空间：

- 路由限流。
- 熔断。
- 上游健康检查。
- 访问日志查询。
- 审计日志。
- 多邀请码或一次性邀请码。
